# ギター指板 音名クイズ（モック）仕様書

- 版: v0.1（モック版）
- 作成日: 2026-08-08
- 対象: HTML / CSS / JavaScript のみで動作するプロトタイプ

---

## 1. 目的

ギターの指板上のどこにどの音があるかを、クイズ形式の反復で身体的に覚えるための練習サービス。

本ドキュメントは、その第一段階として **ビルドツール・サーバサイド・外部ライブラリを一切使わないモック** の仕様を定める。目的は「学習ループが実際に成立するか」をブラウザ上で最短で検証することであり、機能の網羅ではない。

---

## 2. スコープ

### 2.1 このモックに含むもの

| 項目 | 内容 |
| --- | --- |
| 出題形式 | **全弦探しモードのみ**（指定された音名を、指板全体から全て見つけて回答する） |
| 機能 | 出題 / 回答受付 / 正誤判定 / スコア表示 |
| 指板描画 | HTML 要素 + CSS Grid |
| 対応環境 | PC（デスクトップブラウザ）のみ |

### 2.2 このモックに含まないもの（将来拡張）

以下は仕様として意識はするが、v0.1 では実装しない。

- 音の再生（Web Audio API）
- 成績の永続化（localStorage）、学習履歴、弱点分析
- 設定パネル（チューニング変更・フレット範囲変更・対象弦の絞り込み・♯/♭ 表記切り替え・制限時間）
- 他の出題形式（位置 → 音名、音名 → 位置の単一回答、度数・インターバル）
- スマートフォン / タブレット対応レイアウト
- ダークモード
- 制限時間・タイマー

拡張時の指針は「9. 将来拡張を見据えた設計方針」に記載する。

## 3. 用語定義

| 用語 | 定義 |
| --- | --- |
| 弦（string） | 1〜6 で表す。**1弦が最も高音（細い）、6弦が最も低音（太い）**。 |
| フレット（fret） | 0〜7 の整数。0 は開放弦（ナット）を指す。 |
| ポジション | 弦とフレットの組 `(string, fret)`。指板上の 1 マスに対応する。 |
| 音名 | `C, C#, D, D#, E, F, F#, G, G#, A, A#, B` の 12 種。 |
| ピッチクラス | 音名をオクターブを無視して 0〜11 の整数で表したもの。`C = 0`。 |
| ナチュラル音 | ♯ / ♭ の付かない 7 音 `C, D, E, F, G, A, B`。 |
| 問題（question） | 出題された 1 つの音名と、その正解ポジション集合。 |
| セッション | 問題を規定数こなす 1 回のプレイ単位。 |

## 4. 前提条件

### 4.1 チューニング

標準チューニング（EADGBE）固定。開放弦の音を MIDI ノート番号で保持する。

| 弦 | 開放弦の音 | MIDI 番号 | ピッチクラス |
| --- | --- | --- | --- |
| 1弦 | E4 | 64 | 4 (E) |
| 2弦 | B3 | 59 | 11 (B) |
| 3弦 | G3 | 55 | 7 (G) |
| 4弦 | D3 | 50 | 2 (D) |
| 5弦 | A2 | 45 | 9 (A) |
| 6弦 | E2 | 40 | 4 (E) |

### 4.2 フレット範囲

**0〜7 フレット（8 列）** を対象とする。

指板全体（0〜12）は 1 問あたりの探索範囲が広すぎて 1 問が長くなるため、ローポジションに絞る。

この範囲は 8 半音しかなく 1 オクターブに満たないため、次の 2 点が判定・出題ロジックに影響する。

- 同じ音名が同一弦に 2 回出現することはない（1 弦につき 0 箇所または 1 箇所）
- **音名によっては、その音が存在しない弦がある**。例えば C は 1 弦・4 弦・6 弦の 0〜7 フレットには存在せず、正解は 3 箇所しかない。「各弦に必ず 1 つある」という前提を置いてはならない

なお 0〜12 に戻す場合は、12 フレットで開放弦と同じ音名が戻るため「同一弦に 2 箇所」が復活する。`FRET_MAX` の変更だけで両方に対応できるようにしておく。

### 4.3 音名の表記

♯ 表記に統一する（`C#` は使うが `Db` は使わない）。異名同音の扱いはモックのスコープ外とし、将来の設定項目とする。

### 4.4 出題対象の音名

**ナチュラル 7 音（C, D, E, F, G, A, B）のみ** を出題する。

理由:

- 指板の音名把握は自然音の位置を先に固定するのが定石であり、♯ 音はその相対位置として後から覚えられる
- 異名同音の表記問題（`C#` / `Db`）をモック段階で持ち込まずに済む

全 12 音への拡張は将来の設定項目とする。

## 5. ドメインロジック

### 5.1 音名の算出

```js
const NOTE_NAMES = ['C', 'C#', 'D', 'D#', 'E', 'F', 'F#', 'G', 'G#', 'A', 'A#', 'B'];

// index 0 が 1弦
const OPEN_STRING_MIDI = [64, 59, 55, 50, 45, 40];

const FRET_MIN = 0;
const FRET_MAX = 12;

/** ポジションのピッチクラス (0-11) を返す */
function pitchClassAt(stringNo, fret) {
  return (OPEN_STRING_MIDI[stringNo - 1] + fret) % 12;
}

/** ポジションの音名を返す */
function noteNameAt(stringNo, fret) {
  return NOTE_NAMES[pitchClassAt(stringNo, fret)];
}

/** 指定した音名に該当するポジションを全て返す */
function findPositions(noteName) {
  const target = NOTE_NAMES.indexOf(noteName);
  const result = [];
  for (let s = 1; s <= 6; s++) {
    for (let f = FRET_MIN; f <= FRET_MAX; f++) {
      if (pitchClassAt(s, f) === target) result.push({ string: s, fret: f });
    }
  }
  return result;
}
```

### 5.2 正解ポジション数（実装の検算用）

0〜7 フレット・6 弦の範囲における、ナチュラル 7 音の正解フレットと合計数。`-` はその弦に存在しないことを示す。実装後はこの表と一致することを確認する。

| 音名 | 1弦 | 2弦 | 3弦 | 4弦 | 5弦 | 6弦 | 合計 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| C | - | 1 | 5 | - | 3 | - | 3 |
| D | - | 3 | 7 | 0 | 5 | - | 4 |
| E | 0 | 5 | - | 2 | 7 | 0 | 5 |
| F | 1 | 6 | - | 3 | - | 1 | 4 |
| G | 3 | - | 0 | 5 | - | 3 | 4 |
| A | 5 | - | 2 | 7 | 0 | 5 | 5 |
| B | 7 | 0 | 4 | - | 2 | 7 | 5 |

全マス数は 6 弦 × 8 フレット = 48。ナチュラル音の合計 30 と、非ナチュラル 5 音の合計 18 の和が 48 になる（検算が合う）。

1 問あたりの正解数は 3〜5 箇所で、0〜12 フレットのとき（6〜8 箇所）よりおよそ半分になる。

## 6. クイズ仕様

### 6.1 セッション構成

- 1 セッション = **7 問**
- ナチュラル 7 音をシャッフルし、各音を 1 回ずつ出題する（同じ音名が 1 セッション内で重複しない）
- 7 問すべてクリアするとリザルト画面へ遷移する

### 6.2 出題

- 出題文: 「**C** をすべて見つけてください」
- 補助表示: 「残り **3** 箇所」（未発見の正解ポジション数。1 つ見つけるたびに減る）
- 進捗表示: 「3 / 7 問」

### 6.3 回答と判定

指板上のセルをクリックすることで回答する。1 問につき複数回クリックする。

| クリック対象 | 挙動 |
| --- | --- |
| 未回答セル・正解 | セルを **正解状態** にし、残り数を 1 減らす。正解タップ数 +1 |
| 未回答セル・不正解 | セルを **誤答状態** にし、そのセルの実際の音名を表示する。誤答タップ数 +1 |
| すでに正解状態のセル | 何もしない（カウントしない） |
| すでに誤答状態のセル | 何もしない（カウントしない） |

- 誤答してもゲームオーバーにはせず、正解ポジションを全て見つけるまで同じ問題を続ける
- 同一セルの再クリックをカウントしないのは、連打によるスコアの水増し / 悪化を防ぐため

### 6.4 問題クリア

未発見の正解ポジションが 0 になった時点でその問題はクリア。

- 指板全体を一時的に操作不可にする
- 「次の問題へ」ボタンを活性化する（自動遷移はしない。答え合わせを目で確認する時間を確保するため）
- 最終問題の場合はボタンのラベルを「結果を見る」にする

### 6.5 スコア

セッション全体で以下を集計する。

| 指標 | 定義 |
| --- | --- |
| 出題数 | 7（固定） |
| 正解タップ数 | 正解ポジションを引き当てた回数（= 全問の正解ポジション総数 30 と一致する） |
| 誤答タップ数 | 誤ったセルをクリックした回数（同一セルの重複は除く） |
| 正答率 | `正解タップ数 / (正解タップ数 + 誤答タップ数)` を百分率で小数第 1 位まで |

リザルト画面ではこの 4 項目と「もう一度」ボタンを表示する。

## 7. 画面仕様

### 7.1 全体レイアウト（PC 固定）

- 想定最小幅: 1024px
- コンテンツ最大幅: 1100px、中央寄せ
- 単一ページ。画面は状態によって表示を切り替える（ページ遷移なし）

```
┌────────────────────────────────────────────────┐
│  ギター指板 音名クイズ           3 / 7 問  ミス 2 │  ← ヘッダー
├────────────────────────────────────────────────┤
│                                                │
│         C をすべて見つけてください               │  ← 出題エリア
│              残り 2 箇所                        │
│                                                │
├────────────────────────────────────────────────┤
│           ║                                    │
│      1弦  ║ ○ │ ○ │ ○ │ ○ │ ○ │ ○ │ ○ │        │
│      2弦  ● ○ │ ○ │ ○ │ ○ │ ○ │ ○ │ ○ │        │  ← 指板
│      3弦  ║ ○ │ ○ │ ○ │ ○ │ ● │ ○ │ ○ │        │
│      4弦  ║ ○ │ ○ │ ○ │ ○ │ ○ │ ○ │ ○ │        │
│      5弦  ║ ○ │ ○ │ ● │ ○ │ ○ │ ○ │ ○ │        │
│      6弦  ║ ○ │ ○ │ ○ │ ○ │ ○ │ ○ │ ○ │        │
│           0   1   2   3   4   5   6   7        │  ← フレット番号
├────────────────────────────────────────────────┤
│                              [ 次の問題へ ]     │  ← フッター
└────────────────────────────────────────────────┘
```

### 7.2 指板 UI

CSS Grid で構成する。

- 行: 6 行（上から 1 弦 → 6 弦）。TAB 譜の慣習に合わせ、**1 弦を最上段** に置く
- 列: 弦名ラベル列 + 8 列（0〜7 フレット）
- フレット数が少ないとセルが横へ間延びするため、フレット 1 列あたりの幅に上限（100px）を設け、指板全体を中央寄せにする
- 0 フレット（開放弦）列は他より狭い固定幅とし、右側に太いナットの罫線を引いて視覚的に区別する
- 各セルは `<button>` 要素とし、`data-string` / `data-fret` を持つ
- ポジションマーク: 3, 5, 7, 9 フレットに薄い丸印を 1 個、12 フレットに 2 個。実物のインレイと同じく弦と弦の境目に置くため、単発は 3 弦セルの下辺、12 フレットは 2 弦・4 弦セルの下辺に描く。現在のフレット範囲（0〜7）では 3, 5, 7 の 3 個のみが描画される
- 弦を表す横線をセルの上下中央に引く。1 弦を最も細く、6 弦を最も太くする。音名ラベルの可読性を保つため、弦線はセル背景より上・ラベルより下に描く
- 板の下地（木目）とナット部分は、行の上下に少しはみ出させるためセルとは別の背景レイヤーとして描く

```css
.fretboard {
  display: grid;
  grid-template-columns: 48px 56px repeat(12, 1fr);
  grid-template-rows: repeat(6, 44px) 28px; /* 最終行はフレット番号 */
}
```

### 7.3 セルの状態と見た目

| 状態 | 表示 |
| --- | --- |
| 通常 | 指板色（薄い木目調の背景）、ラベルなし |
| ホバー | 明度を上げる、カーソル `pointer` |
| 正解 | 緑背景（`#2e7d32`）、白文字で音名を表示 |
| 誤答 | 赤背景（`#c62828`）、白文字でそのセルの実際の音名を表示 |
| 無効 | `disabled` を付与してクリックとフォーカスを止める |

誤答セルに実際の音名を出すのは、「間違えた場所が何の音だったか」がその場で学習にフィードバックされるため。

グレーアウト（彩度を落とす）は `idle` 状態の指板にのみ適用する。`cleared` / `result` は回答結果を見せる場面であり、そこで彩度を落とすと正誤の色が読み取りにくくなって逆効果になるため、無効化しても色はそのまま残す。

判定済みのセルは、ホバーしても正解 / 誤答の色が上書きされないようにする。

### 7.4 画面状態

| 状態 | 表示内容 |
| --- | --- |
| `idle` | タイトルと「スタート」ボタン。指板はグレーアウトして表示 |
| `answering` | 出題文・残り数・操作可能な指板 |
| `cleared` | 出題文（クリア表示）・操作不可の指板・「次の問題へ」ボタン |
| `result` | セッションのスコア 4 項目・「もう一度」ボタン |

状態遷移:

```
idle ──[スタート]──> answering ──[全正解]──> cleared
                        ↑                        │
                        └──[次の問題へ]──────────┘
                                                 │ (7問目クリア)
                                                 ↓
                                              result
                                                 │
                                                 └──[もう一度]──> answering (新セッション)
```

## 8. 技術構成

### 8.1 制約

- 外部ライブラリ・フレームワーク・CDN 依存なし
- ビルド不要（トランスパイル・バンドルなし）
- ES Modules + 素の DOM API のみ

### 8.2 ファイル構成

```
guitar_onnmei/
├── index.html          # マークアップの骨格。指板セルは JS で生成
├── styles.css          # 全スタイル
├── src/
│   ├── main.js         # エントリポイント。状態管理と DOM の配線
│   ├── music.js        # 音楽理論ドメイン（チューニング・音名算出・ポジション検索）
│   ├── quiz.js         # セッション/問題の生成・判定・スコア集計（DOM 非依存）
│   └── fretboard.js    # 指板の描画とクリックイベント発行
└── docs/
    └── spec.md         # 本ドキュメント
```

`music.js` と `quiz.js` を DOM 非依存に保つのは、後で React 等へ移行する際にロジックをそのまま持ち出せるようにするため。

### 8.3 起動方法

ES Modules は `file://` プロトコルでは CORS 制約により読み込めない。ローカル HTTP サーバ経由で開く。

```
python3 -m http.server 8000
# → http://localhost:8000 を開く
```

### 8.4 対応ブラウザ

Chrome / Safari / Firefox の最新版。ポリフィルは用意しない。

## 9. 将来拡張を見据えた設計方針

モック段階で以下を守っておくと、拡張時の書き直しが最小で済む。

| 拡張項目 | モック段階で守ること |
| --- | --- |
| チューニング変更 | 開放弦は `OPEN_STRING_MIDI` 配列を唯一の情報源とし、音名をハードコードしない |
| フレット範囲変更 | `FRET_MIN` / `FRET_MAX` を定数化し、指板描画・出題ロジック双方がこれを参照する |
| 出題形式の追加 | `quiz.js` は「問題オブジェクト（出題内容 + 正解ポジション集合）」を返す形にし、`main.js` が形式を意識しないようにする |
| 音の再生 | ポジションは常に MIDI 番号を計算できる状態で保持する（ピッチクラスだけに潰さない） |
| 成績の永続化 | スコアは `quiz.js` 内のプレーンオブジェクトとして保持し、シリアライズ可能にしておく |
| ♯/♭ 表記切り替え | 表示用の音名文字列への変換は 1 箇所（`music.js`）に閉じ込める |
| スマホ対応 | 指板のセル寸法を CSS 変数化しておく |

---

## 10. 非機能要件

- クリックからセルの状態が変わるまで 100ms 以内（アニメーションは 150ms 程度のトランジションまで）
- 指板の全セル（48 個）は初期化時に一度だけ生成し、問題ごとに再生成しない。状態のリセットは class の付け外しで行う
- 各セルは `<button>` のため、Tab キーでのフォーカス移動と Enter / Space での回答が標準で動作する
- `aria-label` に「N弦 Mフレット」を設定する

## 11. 未確定事項

以下は実装中に判断が必要になった場合、ユーザーに確認する。

- リザルト画面に音名ごとの内訳（どの音でミスが多かったか）を出すか。学習価値は高いが「最小構成」の線引きを超えるため v0.1 では見送っている
- 1 セッション 7 問という分量が、実際に触ったときに短すぎないか / 長すぎないか
